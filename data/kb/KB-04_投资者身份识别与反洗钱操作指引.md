# 投资者身份识别与反洗钱操作指引（教学样例）

> **重要声明**：本文件为**虚构的教学样例文档**，用于本地 RAG 知识库、角色权限过滤（本文件仅对 `compliance` / `manager` 可见）与评测集演练。
> 所有阈值、时限、字段、流程编号均为示例值，**不是任何真实机构的制度**，不含任何真实客户数据；实际以现行法律法规与所在机构最新制度为准。

## 1. 基本定义

**客户身份识别（KYC）**：在建立业务关系、办理规定金额以上交易或出现疑点时，核实并登记投资者身份信息的过程。
**持续识别**：业务关系存续期间，持续关注客户及其交易，确保信息与实际一致。
**受益所有人**：最终拥有或实际控制客户的自然人（示例表述，具体认定规则以现行规定为准）。

## 2. 三个识别时点

| 时点 | 触发条件（示例） | 主要动作 |
|---|---|---|
| 初次识别 | 开户、首次办理业务 | 核对身份文件、登记基本信息、确认受益所有人 |
| 持续识别 | 存续期间交易监测 | 关注交易与身份/财务状况是否匹配，更新过期资料 |
| 重新识别 | 信息变更、证件到期、出现异常、怀疑资料真实性 | 重新核实并留存记录 |

## 3. 登记字段（示例，均为脱敏字段定义）

| 字段组 | 字段示例 |
|---|---|
| 主体识别 | 客户类型、名称/姓名、证件类型与号码（脱敏存储）、证件有效期 |
| 联系信息 | 联系地址、联系方式、职业或经营范围 |
| 账户信息 | 账户标识、资金来源说明、交易目的 |
| 控制关系 | 受益所有人识别结论、授权办理人 |
| 流程信息 | 识别时间、识别方式、复核人、下次复核日期 |

> **实现约束**：证件号码等敏感字段即使在内部系统中也应脱敏存储与展示；任何情况下**不得进入大模型提示词、日志明文或外部 API 请求体**。

## 4. 可疑情形识别信号（示例）

以下情形需触发人工复核，不作为自动判定结论：

- 交易模式与客户身份、职业、声明的资金来源明显不符；
- 短期内频繁开户、销户、变更关键信息；
- 通过多个账户分散交易以规避常规审核阈值；
- 拒绝提供身份资料或提供明显矛盾的解释；
- 要求将资金划往与业务关系无关的方向；
- 关键联系方式由第三方统一控制且无法说明合理原因。

> 单一信号不构成结论。系统只做**提示与留痕**，最终判断由合规人员作出。

## 5. 报告路径与留痕

1. 系统或业务人员发现信号 → 生成复核工单（含触发信号、时间、关联流水标识）。
2. 合规岗复核 → 记录结论（排除 / 持续观察 / 上报）。
3. 需上报的按机构规定路径处理，**不得由业务人员直接对外沟通**。
4. 全流程留痕：触发、复核、结论、处理时间、经办与复核角色。
5. 记录保存期限以现行规定与机构制度为准，到期按流程销毁。

## 6. 与 AI / 私有化部署相关的特别约束（FDE 场景重点）

| 约束 | 原因 | 落地做法 |
|---|---|---|
| 客户身份信息不出内网 | 数据合规与最小化原则 | 模型与向量库均部署在内网；关闭外发遥测 |
| 敏感字段不进入提示词 | 提示词可能被记录、回放、用于调试 | 检索前做字段级脱敏，仅传必要业务语义 |
| 审计日志独立留存 | 需要可回溯、不可抵赖 | 记录谁在何时查询了哪类资料、命中哪些片段 |
| 权限在检索层强制 | 提示词约束可被绕过 | 按角色过滤可见文档集合，再执行向量检索 |
| 模型不自行下结论 | 反洗钱判断需人工负责 | 系统输出"疑似信号 + 依据"，结论由人工作出 |
| 供应商无法远程访问数据 | 驻场/私有化交付要求 | 无外网出向、密钥本地托管、升级走离线包 |

## 7. 常见问答

**问：可以把客户证件信息发给外部大模型帮着做摘要吗？**
> 不可以。身份信息属于敏感数据，应在本机构可控环境内处理；对外发送既违反最小化原则，也可能违反数据出境与保密要求。私有化部署正是为了解决这类场景。

**问：系统识别到可疑信号能自动冻结账户吗？**
> 不能。系统只提示与留痕，是否采取措施由合规人员按流程决定，避免自动化误判造成不当处置。

**问：审计日志应该记什么？**
> 至少记录：操作者角色、时间、查询内容摘要、命中的文档 doc_id 与片段、检索过滤条件、输出结果摘要。日志本身也要防止被未授权查看。
